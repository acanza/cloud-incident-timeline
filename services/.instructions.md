# Services Implementation Guide

## Overview

This directory contains the application logic for three microservices that run on ECS Fargate:
- `incident-service` — HTTP API for incident management
- `timeline-service` — HTTP API for timeline queries
- `audit-worker` — Asynchronous worker for audit event processing

Infrastructure (ECR repositories, ECS tasks, IAM roles) is managed by Terraform in the `infrastructure/` folder.

Follow these patterns consistently:

|---------|---------|---------|
| ECR Repository | `{project}-{env}-{service}` | `cloud-incident-timeline-dev-incident-service` |

| Internal Port | Service-specific | `incident-service:3001`, `timeline-service:3002`, `audit-worker:3003` |
| Source Code Directory | `src/` | All source code lives here |

## Tech Stack & Implementation Choices

### Recommended Stacks

Pick one and keep it consistent across all services:

**Option A: Node.js + Express (Recommended for simplicity)**
```
- Runtime: Node.js 18+
- Framework: Express.js
- ORM/Client: AWS SDK v3 for DynamoDB/SQS/EventBridge
- Package Manager: npm or yarn
- Port Defaults: 3001, 3002, 3003
```

**Option B: Python + FastAPI**
```
- Runtime: Python 3.11+
- Framework: FastAPI
- Client: boto3 (AWS SDK)
- Package Manager: pip + requirements.txt
- Port Defaults: 8001, 8002, 8003
```

**Option C: Go**
```
- Runtime: Go 1.20+
- Framework: Gin or Echo
- Client: AWS SDK for Go v2
- Port Defaults: 8080 (adjust per service)
```

### Guidelines

- All services must use the same tech stack (consistency across the team)
- Minimize external dependencies (keep images small for cost)
- No hardcoded credentials; rely on task IAM roles
- Health check endpoints required (ECS/ALB expect `GET /health` or similar)

## Local Development

### Prerequisites

- Docker and Docker Compose installed
- AWS CLI configured (optional, for local testing against real AWS)

### Running Services Locally

Create `docker-compose.yml` in the **root** of the repository:

```yaml
version: "3.8"

services:
  incident-service:
    build: ./services/incident-service
    ports:
      - "3001:3001"
    environment:
      DYNAMODB_TABLE_NAME: incidents
      AWS_REGION: eu-west-3
    depends_on:
      - dynamodb-local

  timeline-service:
    build: ./services/timeline-service
    ports:
      - "3002:3002"
    environment:
      DYNAMODB_TABLE_NAME: incident_timeline
      AWS_REGION: eu-west-3
    depends_on:
      - dynamodb-local

  audit-worker:
    build: ./services/audit-worker
    environment:
      DYNAMODB_TABLE_NAME: audit_logs
      SQS_QUEUE_URL: http://sqs-local:9324/queue/audit-events
      AWS_REGION: eu-west-3
    depends_on:
      - dynamodb-local
      - sqs-local

  dynamodb-local:
    image: amazon/dynamodb-local:latest
    ports:
      - "8000:8000"
    command: "-jar DynamoDBLocal.jar -sharedDb"

  sqs-local:
    image: softwaremill/elasticmq-native:latest
    ports:
      - "9324:9324"
```

### Running All Services

```bash
# From repository root
docker-compose up
```

### Running a Single Service

```bash
docker-compose up incident-service
```

### Tearing Down

```bash
docker-compose down
```

## Building Docker Images

The Dockerfile for each service must:

1. **Specify a base image** (keep it minimal; use `alpine` variants for size)
2. **Set working directory** to a consistent path (e.g., `/app`)
3. **Copy source code** into the image
4. **Install dependencies** (npm install, pip install, go build, etc.)
5. **Expose the service port** (via `EXPOSE`)
6. **Define a health check** (recommended but optional)
7. **Start the application** (via `CMD` or `ENTRYPOINT`)

### Example Dockerfile (Node.js)

```dockerfile
FROM node:18-alpine

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY src ./src

EXPOSE 3001

HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD node -e "require('http').get('http://localhost:3001/health', (r) => {if (r.statusCode !== 200) throw new Error(r.statusCode)})"

CMD ["node", "src/index.js"]
```

### Example Dockerfile (Python)

```dockerfile
FROM python:3.11-alpine

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY src ./src

EXPOSE 8001

HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD python -c "import http.client; http.client.HTTPConnection('localhost', 8001).request('GET', '/health')"

CMD ["python", "-m", "uvicorn", "src.main:app", "--host", "0.0.0.0", "--port", "8001"]
```

## Building and Pushing Images to ECR

### Step 1: Build Images Locally

```bash
cd services/incident-service
docker build -t incident-service:dev .

cd ../timeline-service
docker build -t timeline-service:dev .

cd ../audit-worker
docker build -t audit-worker:dev .
```

### Step 2: Tag Images for ECR

You need the ECR repository URLs. After running `terraform apply`, get them from Terraform outputs:

```bash
cd infrastructure/environments/dev
terraform output
```

Example output:
```
ecr_incidents_service_url = "123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-incident-service"
ecr_timeline_service_url = "123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-timeline-service"
ecr_audit_worker_url = "123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-audit-worker"
```

Tag the images:

```bash
docker tag incident-service:dev 123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-incident-service:dev
docker tag timeline-service:dev 123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-timeline-service:dev
docker tag audit-worker:dev 123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-audit-worker:dev
```

### Step 3: Authenticate Docker with ECR

```bash
aws ecr get-login-password --region eu-west-3 | docker login --username AWS --password-stdin 123456789012.dkr.ecr.eu-west-3.amazonaws.com
```

### Step 4: Push Images

```bash
docker push 123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-incident-service:dev
docker push 123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-timeline-service:dev
docker push 123456789012.dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-audit-worker:dev
```

### Automate with Makefile

Add to the **root Makefile**:

```makefile
.PHONY: build-services push-services

build-services:
	docker build -t incident-service:dev services/incident-service
	docker build -t timeline-service:dev services/timeline-service
	docker build -t audit-worker:dev services/audit-worker

push-services: build-services
	aws ecr get-login-password --region eu-west-3 | docker login --username AWS --password-stdin $$(aws sts get-caller-identity --query Account --output text).dkr.ecr.eu-west-3.amazonaws.com
	docker push $$(aws sts get-caller-identity --query Account --output text).dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-incident-service:dev
	docker push $$(aws sts get-caller-identity --query Account --output text).dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-timeline-service:dev
	docker push $$(aws sts get-caller-identity --query Account --output text).dkr.ecr.eu-west-3.amazonaws.com/cloud-incident-timeline-dev-audit-worker:dev
```

Then simply:

```bash
make push-services
```

## AWS Service Integration

### DynamoDB

Each service gets its own DynamoDB table:

| Service | Table Name | IAM Permission |
|---------|------------|-----------------|
| `incident-service` | `cloud-incident-timeline-dev-incidents` | Read/Write `incident-service` table |
| `timeline-service` | `cloud-incident-timeline-dev-incident-timeline` | Read `incident-service` table, Write `incident-timeline` table |
| `audit-worker` | `cloud-incident-timeline-dev-audit-logs` | Write `audit-logs` table |

**Table name is injected as environment variable by ECS:**

```bash
# Example ECS environment variable
DYNAMODB_TABLE_NAME=cloud-incident-timeline-dev-incidents
```

**Access from your service:**

```javascript
// Node.js example
const { DynamoDBClient } = require("@aws-sdk/client-dynamodb");
const client = new DynamoDBClient({ region: "eu-west-3" });
// AWS credentials come from task IAM role automatically
```

```python
# Python example
import boto3
dynamodb = boto3.resource('dynamodb', region_name='eu-west-3')
table = dynamodb.Table(os.environ['DYNAMODB_TABLE_NAME'])
# AWS credentials come from task IAM role automatically
```

### EventBridge

`timeline-service` publishes events to EventBridge custom event bus.

**Environment variables injected by ECS:**

```bash
EVENTBRIDGE_BUS_NAME=cloud-incident-timeline-dev-bus
AWS_REGION=eu-west-3
```

### SQS

`audit-worker` consumes messages from SQS queue.

**Environment variables injected by ECS:**

```bash
SQS_QUEUE_URL=https://sqs.eu-west-3.amazonaws.com/123456789012/cloud-incident-timeline-dev-audit-queue
AWS_REGION=eu-west-3
```

## Security Constraints

### ✅ DO

- ✅ Use AWS IAM task roles for authentication (no hardcoded keys)
- ✅ Read secrets from environment variables injected by ECS
- ✅ Validate all external inputs
- ✅ Log errors and warnings (CloudWatch Logs capture container logs automatically)
- ✅ Return proper HTTP status codes (ALB health checks depend on `200 OK`)

### ❌ DON'T

- ❌ Hardcode AWS access keys, secret keys, or any credentials
- ❌ Log sensitive information (credentials, PII, secrets)
- ❌ Accept unvalidated input from HTTP requests
- ❌ Store secrets in `.env` files committed to Git
- ❌ Make direct AWS API calls without verifying IAM permissions first

### Credentials Best Practice

**Never do this:**

```javascript
// ❌ WRONG
const client = new DynamoDBClient({
  credentials: {
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY
  }
});
```

**Always do this:**

```javascript
// ✅ CORRECT
const client = new DynamoDBClient({
  region: process.env.AWS_REGION || 'eu-west-3'
  // Credentials come from task IAM role automatically
});
```

## Deployment Workflow

This is the **expected order** for deploying the infrastructure and services:

1. **Format Terraform code**
   ```bash
   cd infrastructure
   make fmt
   ```

2. **Validate Terraform**
   ```bash
   make validate
   ```

3. **Plan infrastructure changes**
   ```bash
   make plan
   ```

4. **Apply infrastructure** (creates ECR repositories, ECS cluster, etc.)
   ```bash
   make apply
   ```

5. **Build and push service images**
   ```bash
   make push-services
   ```

6. **Create or update ECS services**
   ```bash
   cd infrastructure
   make apply  # Re-run to deploy ECS services with new images
   ```

7. **Validate deployment**
   ```bash
   # Check ALB DNS name from Terraform outputs
   curl http://<alb-dns>/incidents/health
   curl http://<alb-dns>/timeline/health
   ```

## Troubleshooting

### ECS Task Fails with "Image Pull Error"

**Cause**: Docker image not pushed to ECR or wrong tag.

**Fix**:
```bash
make push-services
# Then manually update ECS task definition or re-run terraform apply
```

### ALB Returns 502 Bad Gateway

**Causes**:
- Health check endpoint not responding with `200 OK`
- Service not listening on the correct port
- Security group blocking inbound traffic

**Debug**:
```bash
# SSH into ECS task (if available) or check CloudWatch Logs
aws logs tail /ecs/cloud-incident-timeline-dev-incident-service --follow
```

### Service Can't Access DynamoDB

**Cause**: IAM task role doesn't have `dynamodb:*` permissions.

**Fix**: Check `infrastructure/modules/iam/main.tf` and verify the task role policy includes DynamoDB access.
